# 字体、注释与内容间距规则回归设计

## 目标

将已确认的注释、组合型证据、大型证据数字、Q&A 间距和内容驱动高度规则写入唯一权威流程，并让生成器、验证器、生成文件和插件镜像执行同一套规则。解决现有示例中因 `margin-top: auto` 吸收剩余高度而出现的 180px、245px 等非规范间距。

## 已确认的规则

1. 注释指引数字如 `【1】`、`【2】`、`【3】` 显示时去除括号，并且不得被拆成单独一行。
2. 除注释说明文本外，所有文字叶节点均使用对应语言区域的 `100%` 行高。注释说明文本使用 `0px` 行高，仅作用于脚注、来源说明和免责声明正文；注释指引数字保留免责声明字号和 `100%` 行高，并且不得单独成行。
3. `xx%用户认可` 等组合型内容视为不可拆分单元，数字、百分号和“用户认可”不得跨行或拆成多个语义组。
4. Q&A 每组回答结束到下一组问题开始的组间距为 `60px`；同一组 Q 与 A 的内部间距保持现有规则。
5. 大型证据数字按同页组数决定字号：2 组优先 `75px`；3 组优先 `45px`；4 组及以上强制 `45px`。同页大型证据数字统一字号。
6. 内容区块之间遵守 `40px` 内容间距。禁止用 `margin-top: auto`、`justify-content: space-between` 或同类剩余空间分配制造内容间距；非 KV 高度由最下方非出血内容加 `60px` 下安全边距确定。

## 方案与选择

采用全链路同步方案：

- 根 `SKILL.md`：写入规则、异常处理和验证要求。
- `brand/source.json`：增加注释行高和 Q&A 组间距令牌，保持非颜色品牌值集中管理。
- `scripts/sync-brand.py`：生成新增令牌和对应精简规则。
- 生成器和 HTML 模板：移除会吸收剩余空间的内容布局类，按内容顺序和固定间距布局，并为不可拆分组合提供稳定容器。
- 验证器与测试：增加注释独行、组合型内容拆分、大型证据字号统一、Q&A 组间距和自动剩余空间检测。
- 运行 `python scripts/sync-brand.py` 更新根生成文件和插件镜像。
- 在当前产品企划示例上重新生成 HTML，作为回归样本。

只修改文档或只修改生成 CSS 都无法约束后续生成流程，因此不采用。

## 数据流与边界

`brand/source.json` 是新增非颜色令牌的源；`brand/generated/*` 及插件镜像只通过 `scripts/sync-brand.py` 更新。模板配色继续由模板的 `preview.md` 和 `design.md` 管理。当前示例继续使用已有 `clearproof-green`、`light`、`clean` 和占位符图像模式。

注释括号只在可见 HTML 中移除，来源台账保留原文。组合型内容的不可拆分约束只作用于该内容单元，不改变普通中文文案的语义换行规则。

## 验证策略

### RED 基线

- 现有示例截图中第 2 页卡片组计算出 `180px` 的 `margin-top`，第 3 页注释组计算出 `245px` 的 `margin-top`。
- 原因可由现有生成器的 `.push-bottom { margin-top: auto; }` 和多个 `push-bottom` 内容节点稳定复现。
- 现有规则没有阻止注释数字独行、组合型证据拆分或页面大型证据字号混用。

### GREEN 验证

1. 先添加会在旧实现上失败的单元和静态契约测试。
2. 修改源令牌、规则、生成器和验证器，使新增测试通过。
3. 运行同步检查、单元测试、静态 HTML、运行时和全量渲染验证。
4. 逐页检查当前产品企划生成截图，确认相邻区块为 40px、Q&A 组间距为 60px、非 KV 页面不再包含自动吸收的额外空白。

## 风险与处理

- 注释说明文本行高从通用 `100%` 改为专项 `0px`，必须限制在注释说明组件；注释指引数字继续使用 `100%` 行高，不能覆盖普通正文或引导数字。
- 组合型内容不可拆分可能增加个别切片高度；若无法排下，按既有规则报告切片并调整内容容器或高度，不缩小字号。
- 删除自动剩余空间后，旧的固定高度可能产生溢出；生成器必须先按内容底部重新计算非 KV 高度，再执行渲染验证。
